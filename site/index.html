The first tool

Start with the process view Linux should have had.

lens-top combines a fast terminal interface, stable structured output and careful diagnostics without becoming another privileged management agent.

01

Useful immediately

Run it interactively, pipe a plain snapshot, or feed versioned JSON into another system. The default follows the terminal it is given.

See output modes →
02

Built for reality

Handles short-lived processes, PID reuse, missing permissions, tiny terminals and broken pipes without turning routine Linux behaviour into a crash.

Read the collection model →
03

Read-only by design

No kill, renice or restart controls. Lens helps operators understand the system first and leaves mutation to explicit tools and workflows.

Understand the boundaries →
Shared language

Not a bag of unrelated commands.

Every Lens tool is designed to share entities, relationships, filtering, output contracts and terminal behaviour.

01

Processes connect to context

Users, parents, services, cgroups and containers belong in the model, not in separate mental silos.

02

Findings carry evidence

Diagnostics are deterministic and cautious. They explain what was observed, what it may mean and which entity is involved.

03

Automation is first-class

Plain text is readable; JSON is explicit; JSON Lines is streamable. The same snapshot feeds all three.

04

Future tools reuse the core

Services, logs, disk and networking will compose around the same model instead of shipping duplicate collectors and incompatible flags.

shell 
# Build the first release from source
$ cargo build --release --locked -p lens-top

# Launch the repeatable demo
$ ./target/release/lens-top --demo

# Machine-readable snapshot
$ lens-top --json --sort memory --limit 20
Predictable by default

Made for humans, pipes and CI.

The terminal UI is only one view. Redirect stdout and Lens emits a single plain snapshot automatically. Ask for JSON when the contract matters.
