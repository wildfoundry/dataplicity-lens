Lens / Roadmap
Honest by design

One real tool first.

The shared platform is designed for a family. The repository only claims binaries that actually exist.

v0.1 · lens-top

Processes and host health

Process collection, session-local CPU and I/O trends, search, filters, sorting, grouping, details, findings, plain text, JSON, JSON Lines, packages and deterministic demo mode.

Built
lens-services

Service health in context

Dependencies, startup duration, restart loops, processes and related logs—connected through the same model rather than a parallel service-only universe.

Planned
lens-logs

Logs that reveal shape

Journal and file sources, repeated-message folding, rate changes, severity filters and crash context linked back to services and processes.

Planned
lens-disk

Storage with responsibility

Filesystems, mounts, block devices, growth, inodes and deleted-but-open files, connected to the processes and services responsible.

Planned
lens-net

Networking with ownership

Interfaces, addresses, routes, listeners, DNS, process ownership and evidence-led connectivity diagnosis.

Planned
lens-health

Composed system findings

A higher-level health view built from mature shared probes. It must not create duplicate collectors or a second diagnostics language.

Later
A roadmap is not a product catalogue.

Later names describe direction and architectural intent. There are no empty placeholder binaries and no promise that sequence will ignore evidence from real users.
